# site as game — дизайн пересборки

## цель

сделать из текущего статического редактора маршрутов цельный, понятный и устойчивый мини-продукт. автор собирает короткий мир из 3–7 комнат, проверяет его как игру и получает автономный ZIP, который можно открыть локально или выложить на GitHub Pages.

основная идея и название `ROOM / ROOM` сохраняются. меняются подача, тексты, визуальная система, устойчивость к повреждённым данным и оформление публикации.

## что найдено в текущей версии

- в `styles.css` несколько поздних слоёв переопределяют ранние правила; из-за этого систему трудно поддерживать и легко получить расхождение desktop/mobile;
- интерфейс использует разные регистры и формулировки: часть действий названа по функции, а не по реальному результату;
- импортированный JSON может принести неограниченный `image.src`, большой объём данных или неподходящую схему;
- источник изображения попадает в `background-image` напрямую, поэтому его нужно проверять до сохранения и отображать безопасным способом;
- экспорт собирает HTML и JSON из пользовательских данных; экранирование нужно сделать единым и проверять на закрывающие теги и управляющие символы;
- сообщения об ошибках и пустых состояниях местами сообщают о проблеме, но не подсказывают следующий шаг;
- README описывает только задание для агента и не помогает пользователю запустить, собрать и опубликовать проект;
- в репозитории нет готового workflow для GitHub Pages и базовых метаданных публикации.

## голос и редакторские правила

тексты пишутся по профилю `chebaturkin-clear-copy` и двум референсным проектам:

- начало фраз, заголовков, подписей и кнопок — со строчной буквы;
- имена, бренды и технические обозначения сохраняют нормативный регистр: `ROOM / ROOM`, `JSON`, `ZIP`, `GitHub Pages`, `localStorage`, `HTML`;
- тон спокойный, тёплый и прямой; без агентского пафоса, искусственных обещаний и давления;
- действие называется фактически: «скачать ZIP», «открыть JSON», «начать заново», «проверить отсюда»;
- ошибка объясняет, что исправить и в каких пределах, если ограничение известно;
- подсказка отвечает на вопрос пользователя, а не повторяет название поля;
- художественный текст шаблонов остаётся живым, но интерфейс не делает вид, что гарантирует прохождение, продажи или поисковую видимость.

## визуальное направление

направление: авторская бумажная карта и редакционный стол.

- палитра: тёплый бумажный фон, чернила, приглушённый серо-коричневый текст и один терракотовый акцент;
- типографика: характерная кириллическая display-гарнитура для названий и нейтральная моноширинная/гротескная гарнитура для интерфейса;
- форма: тонкие рамки, номера, координаты, стрелки, простые SVG-знаки, асимметричные поля и заметные разделители;
- запрещённые приёмы: градиенты, glassmorphism, неон, pill-кнопки, декоративные баблы, bento-сетки и гигантский hero-блок;
- motion: короткие появления и переходы, отключаемые через `prefers-reduced-motion`;
- доступность: видимый `:focus-visible`, рабочий skip-link, корректные роли, touch-цели и читаемые контрасты.

## пользовательский сценарий

### редактор

1. пользователь видит короткое объяснение продукта и выбирает один из трёх шаблонов;
2. в списке комнат выбирает узел, в карте видит связи, в свойствах меняет название, описание, локальное изображение, условия и переходы;
3. статус маршрута показывает готовность, конкретную ошибку или замечание и переводит к проблемной комнате;
4. изменения сохраняются в браузере, JSON можно сохранить/открыть, историю можно отменить и вернуть;
5. кнопка экспорта доступна только для корректного маршрута и создаёт автономный ZIP.

### игра

1. режим игры показывает только маршрут, текущую комнату и действия;
2. заблокированный переход объясняет, какое условие нужно выполнить;
3. прогресс сохраняется локально и может быть сброшен;
4. после прохождения доступны понятные действия: начать заново или вернуться к карте.

## технические изменения

### нормализация и хранение

- ввести единые лимиты для названия проекта, названия комнаты, текста, подписей, количества флагов, переходов и размера изображения;
- принимать изображения только как `data:image/jpeg`, `data:image/png` или `data:image/webp` до 8 мб; неподходящие или повреждённые data URL не сохранять;
- при импорте нормализовать проект до схемы v2 и показывать исправляемую ошибку, если файл не читается;
- сохранять состояние только через безопасные обёртки `localStorage`, с ясным сообщением при недоступном хранилище или переполнении.

### вывод данных

- для HTML-атрибутов, текста, заголовка и inline JSON использовать отдельные безопасные функции экранирования;
- отображать пользовательское изображение через проверенный `img`/локальный путь, а не через необработанную CSS-строку;
- экспортировать только нормализованные данные и фиксированные имена файлов;
- проверить ZIP на пустые записи, корректные размеры и открытие результата в браузере.

### структура CSS

- собрать переменные, базовые элементы, панели, режим игры и адаптивные правила в последовательные разделы;
- убрать дублирующиеся поздние переопределения и оставить один источник правды для размеров, отступов, цветов и брейкпоинтов;
- сохранить desktop и mobile режимы, включая горизонтальную ленту шаблонов и вкладки панелей.

### GitHub Pages

- добавить `.github/workflows/pages.yml` для публикации корня репозитория как статического сайта;
- добавить `.nojekyll`, если это требуется выбранной схемой публикации;
- переписать `README.md`: что это, как открыть локально, как использовать редактор, как экспортировать маршрут, как включить GitHub Pages и какие ограничения есть у браузерного хранения;
- добавить короткое описание и тему в метаданные HTML без выдуманных внешних сервисов или гарантий.

## проверка

- синтаксис `app.js` и отсутствие ошибок при загрузке страницы;
- ручной проход: новый проект, смена шаблона, добавление/удаление/дублирование комнаты, флаги, переходы, старт, импорт JSON, экспорт JSON, экспорт ZIP, undo/redo;
- негативные сценарии: повреждённый JSON, неизвестные цели и флаги, пустые названия, слишком большой/неподходящий файл изображения, переполненное хранилище;
- игра: старт, заблокированная дверь, установка флага, достижение всех комнат, сброс, прямой hash-маршрут;
- desktop и mobile, клавиатура, `prefers-reduced-motion`, доступные имена и видимый focus;
- локальная проверка workflow и README на соответствие фактическому запуску.

## границы

в эту пересборку не входят backend, аккаунты, аналитика, мультиплеер, внешняя AI-модель, отправка данных на сервер и автоматическая публикация в удалённый GitHub без отдельного доступа. локальная папка и готовая конфигурация GitHub Pages входят.
